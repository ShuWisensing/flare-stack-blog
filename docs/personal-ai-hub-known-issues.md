## P1 / HUB-15、22：向量与重排缓存指纹不完整

- 现象：embedding 缓存未区分 query/document，text_hash 会合并空白；rerank 缓存仅包含候选 ID，没有候选内容或知识版本。

- 验证线索：只读调用现有 hash 函数，两个缩进语义不同的 Python 片段产生相同键；其余为源码确认，尚未证明所有历史缓存都存在错误。
- 下一步：指纹包含精确输入、角色、模型修订、instruction、预处理、候选内容和知识 generation；新建 namespace，保留旧缓存，不自动删除。

## P1 / HUB-16、17：网页过碎与长代码截断

- 下一步：先做正文提取、标题与 token 感知分块、代码行范围和父块映射；从保存的原始资料构建新 generation，不覆盖原始文件或旧派生数据。

## P1 / HUB-69：网页派生正文中存在控制字符；资料更新未标记依赖知识过期

- 现象：已有网页快照提取结果含 NUL 等不可见字符；旧资料被新版本替换后，引用旧资料的知识页还可能进入默认检索。
- 影响：降低编码与知识检索质量，旧结论可能被继续使用。

- 验证线索：在已保存 DeepSeek 网页文本中发现控制字符；更新原文后检查引用该来源的知识页状态及索引对象。
- 下一步：派生正文去除非法控制字符；旧来源的知识标记待复核，不再参与默认问答，重新确认新证据后生效。

## P1 / HUB-70：解析失败误阻塞现有知识库

- 现象：新文档尚未写入目录时，解析失败也将整个知识发布状态标为 failed。
- 影响：上传损坏 PDF 等资料后，已有正常知识库会被错误停用。
- 判断：作业未区分解析阶段与已修改目录后的构建阶段。
- 验证：上传损坏 PDF 应作业失败、原知识仍可读取；索引构建失败则必须阻塞并支持显式重建，不能自动换旧模型或掩盖更新失败。
- 下一步：记录作业阶段，在确认原目录未变的解析失败分支保持原发布状态；增加独立重建入口。
